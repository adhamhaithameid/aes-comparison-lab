    Core concepts you need to understand before diving into the interactive modules

    Plaintext & Ciphertext

    Plaintext

    The original readable data you want to protect. In AES, plaintext is processed in 128-bit blocks (16 bytes). If your data isn't a multiple of 16 bytes, it must be padded.

    Example: The string "Hello, World!!!" is exactly 16 bytes — one AES block.

    Ciphertext

    The encrypted output that appears random without the key. AES produces ciphertext of the same size as the input block (plus padding if needed).

    Example: 3ad77bb40d7a3660a89ecaf32466ef97

    Keys & Symmetric Encryption

    AES is a symmetric key algorithm — the same key is used for both encryption and decryption. This means both sender and receiver must share the secret key securely beforehand.

    Key Size Rounds Security Level Use Case
    AES-128 10 Good General purpose, fast
    AES-192 12 Better Government, defense
    AES-256 14 Best Maximum security

    Rounds

    Each AES encryption consists of multiple rounds of transformations. More rounds = more security but slower performance.

    Round Type Operations Count (AES-128)
    Initial Round AddRoundKey only 1
    Main Rounds SubBytes → ShiftRows → MixColumns → AddRoundKey 9
    Final Round SubBytes → ShiftRows → AddRoundKey (no MixColumns) 1

    Key Expansion

    The original cipher key is expanded into round keys — one for each round's AddRoundKey operation. AES-128 uses a 16-byte key expanded to 176 bytes (11 round keys).

    Block Cipher vs. Mode of Operation

    AES is a block cipher — it encrypts one 16-byte block at a time. A mode of operation defines how to encrypt data longer than one block.

    Mode Full Name Authentication Parallelizable Common Use
    ECB Electronic Codebook No Yes Never for messages
    CBC Cipher Block Chaining No No (decrypt only) Legacy systems
    GCM Galois/Counter Mode Yes Yes TLS 1.3, modern apps
    CTR Counter Mode No Yes Disk encryption

    Confidentiality vs. Integrity vs. Authenticity

    Confidentiality

    Ensures only authorized parties can read the message. AES alone provides this.

    AES provides

    Integrity

    Ensures the message hasn't been tampered with. AES alone does NOT provide this.

    Needs MAC

    Authenticity

    Ensures the message came from the claimed sender. Requires authentication.

    Needs MAC
    Common Mistake: Using AES-ECB or AES-CBC without a MAC (Message Authentication Code) means an attacker can modify ciphertext without detection. Always use authenticated encryption like AES-GCM.

    Authenticated Encryption (AEAD)

    AEAD (Authenticated Encryption with Associated Data) provides confidentiality, integrity, and authenticity in a single operation. AES-GCM is the most widely used AEAD mode.
