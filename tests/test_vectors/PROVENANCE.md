# Test-vector provenance

All test vectors in this directory are **official NIST test data**, obtained as
verbatim copies of NIST Cryptographic Algorithm Validation Program (CAVP)
response files (`.rsp`). None of the expected values were generated by either
implementation in this project, and none were invented by hand.

## Files and sources

| File | Origin |
|------|--------|
| `ECBGFSbox128.rsp`  | NIST CAVS 14.0 "GFSbox" known-answer tests for AES-128 ECB (4 cases) |
| `ECBVarTxt128.rsp`  | NIST CAVS 14.0 variable-plaintext KATs for AES-128 ECB (32 cases) |
| `ECBVarKey128.rsp`  | NIST CAVS 14.0 variable-key KATs for AES-128 ECB (32 cases) |
| `ECBMMT128.rsp`     | NIST CAVS 14.0 multi-block-message tests for AES-128 ECB (10 cases) |
| `gcmEncryptExtIV128_subset.rsp` | Extracted subset of NIST CAVS 14.0 `gcmEncryptExtIV128.rsp` (external-IV GCM encrypt KATs, AES-128, 96-bit IV, 128-bit tag) |
| `gcmDecrypt128_subset.rsp`      | Extracted subset of NIST CAVS 14.0 `gcmDecrypt128.rsp` (GCM decrypt KATs **including official `FAIL` authentication-failure cases**) |
| `fips197_vectors.h`             | FIPS 197 Appendix B and Appendix C.1 known-answer vectors, transcribed from the published standard |

Download commands used (mirrors that carry the NIST files verbatim; checked into
this repository for reproducibility):

```sh
BASE=https://raw.githubusercontent.com/pyca/cryptography/main/vectors/cryptography_vectors/ciphers/AES
curl -fsSL "$BASE/ECB/ECBGFSbox128.rsp"  -o tests/test_vectors/ECBGFSbox128.rsp
curl -fsSL "$BASE/ECB/ECBVarTxt128.rsp"  -o tests/test_vectors/ECBVarTxt128.rsp
curl -fsSL "$BASE/ECB/ECBVarKey128.rsp"  -o tests/test_vectors/ECBVarKey128.rsp
curl -fsSL "$BASE/ECB/ECBMMT128.rsp"     -o tests/test_vectors/ECBMMT128.rsp
curl -fsSL "$BASE/GCM/gcmEncryptExtIV128.rsp" -o /tmp/gcmEncryptExtIV128.rsp
curl -fsSL "$BASE/GCM/gcmDecrypt128.rsp"      -o /tmp/gcmDecrypt128.rsp
python3 scripts/extract_gcm_subset.py /tmp/gcmEncryptExtIV128.rsp /tmp/gcmDecrypt128.rsp tests/test_vectors
```

The two `_subset.rsp` files were produced by `scripts/extract_gcm_subset.py`
from the full NIST files. The full files are ~2.9 MB each because they cover
every (plaintext length x AAD length) combination; the subsets keep a
deterministic selection of sections (PTlen in {0, 128, 504, 512, 1024} bits,
AADlen in {0, 160, 384} bits; first 2 / 4 Count blocks per section) in the
original file format. The extractor script prints how many sections/cases were
kept, and `tests/test_plan.md` records the totals that were actually executed.

## Why ECB vectors are used for the from-scratch implementation

ECB mode with no padding applies the raw AES-128 block cipher to each
16-byte block independently, so the ECB KAT files are exactly known-answer
tests for the block cipher itself. ECB is used **only for validation**; it is
not offered as a file-encryption mode anywhere in this project.
